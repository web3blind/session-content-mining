# Large SQLite corpus

Before promising a complete semantic review, measure the selected corpus by exact message IDs, roles, text lengths and exact-content hashes. Report enumeration, byte traversal, deduplication and semantic reading separately. A script fetching or hashing every text is NOT a model reading every text.

The simple inventory can time out on a multi-gigabyte state.db: a global invalid-timestamp count scans the table, and ORDER BY session_id,timestamp,id can choose a slow non-covering index. Inspect EXPLAIN QUERY PLAN read-only. Do not add production indexes or change the database for content mining.

Use bounded keyset reads ordered by integer message ID when required. Pin a maximum ID and the requested time boundaries, record every scanned ID interval, persist selected metadata after each batch, and validate disjointness and total reconciliation. Investigate invalid timestamps and missing session records. Do not derive time membership from ID order. No title/source/activity filters.

If batches use separate connections, label the manifest as bounded live reads, NOT one transactionally frozen snapshot. Detect in-period additions and edited content before a final completeness claim. Preserve the original manifest and record deltas separately.

Exact-content duplicates can reuse a review only after the unique content was actually read, with every occurrence mapped back to session/message IDs and relevant surrounding context. Hash equality is not semantic review; copied instructions and repeated imports are not new author events. Do not silently strip large messages, embedded context or error reports to fit a model window.

When a local read-only corpus has no occurrence hash index, build one bounded in-memory hash-to-representative-ID map from the manifest-scoped occurrences instead of issuing one full-table lookup per reviewed hash. Keep reuse strictly anchored to the earliest unread gap, verify byte-identical Unicode slices against previously covered ranges, and record reuse separately from newly displayed characters. This avoids a slow helper timing out without turning traversal into semantic review.

Persist normalized-text offsets and the unique-character counter at each requested checkpoint, including a partial long message; do not wait for message completion. Compute the remaining authorized character budget programmatically from committed range unions minus validated reuse before every display; pass min(slice_size, remaining) to the renderer. Never subtract batches mentally: repeated exact-reuse batches make manual budget estimates drift. When a renderer adds exact-reuse credit inside its display loop, include all not-yet-attested pending display spans in both the reuse admission check and the remaining display budget; committed-range accounting alone can overrun the ceiling within one call. If a display exceeds the ceiling, record actual displayed versus credited characters explicitly, preserve a pre-repair ledger backup, leave any uncredited tail pending, and disclose the overrun rather than pretending the limit was respected. If a tool returns only an execution label instead of the transcript body, do not checkpoint its ranges: re-display small explicit slices (around 8000 characters) until the text is actually available. Withdraw any accidentally committed opaque-output spans; keep later genuinely read spans but resume from the first gap. Preserve a full baseline range-map backup before repairing coverage: older ledgers may contain explicit evidence reads outside batch ranges, so rebuilding from batches alone can silently discard verified history.

When resuming a legacy ledger whose `unique_chars_read` is a union by whole normalized-message hash, do not call substring-reused ranges newly displayed content: that union still increases for a reused substring inside a different whole-message hash. Preserve the legacy counter for continuity, but report a separate incremental union of baseline ranges plus genuinely displayed ranges, and list full-hash reuse, substring reuse and display occurrences separately. Validate substring donors against earlier explicitly displayed spans before crediting reuse. Before indexing a donor or printing gaps, assert that the requested batch/item/message matches the live earliest-gap cursor and that start/end lie within that exact batch item; a long message can continue as a later item in the same batch, not necessarily item zero of the next batch. Reject mismatches without receipts or coverage credit.

When continuing an existing wave with a legacy baseline-rebuilding save helper, snapshot the current checkpoint first and preserve newer tool-message ranges, reviewed-tool IDs, candidate supplements and source metadata after each rebuild. Recompute message/session counts from the merged result; a correct UA union does not prove non-UA progress survived.

Take the resume baseline and batch count from the current range ledger, not narrative checkpoint numbers in findings. If a baseline already exists, validate it and preserve it rather than overwriting it; fail closed on a mismatch. Narrative counters can drift while the actual range union remains correct.

When validating a resumed ledger, allow older rows without a stored normalized hash: derive only the missing hashes from the canonical read-only source and the same normalizer. Do not discard those baseline ranges or rewrite their provenance merely to make the new validator pass. Assert baseline-row preservation and candidate/update/media preservation separately from the incremental union.

Validate the counter by unioning actually displayed spans per exact normalized-content hash and subtracting previously read content. Keep duplicate occurrence/context accounting separate. A legacy finalizer that rebuilds coverage or candidates from a fixed old batch must not overwrite newer incremental checkpoints; merge and validate against the existing ledger instead.

Validate candidate source pointers against the canonical unit text before finalizing: role, session/message ID, actually read offsets, exact author wording, and tool values must all match. Never reconstruct numeric unit IDs from memory after long batches; a plausible nearby index may point to an unrelated tool. Assert every cited source has a fully read span (or explicitly cite its partial span), then recheck factual quantities and attribution from those exact records. Preserve a correction audit and disable superseded finalizers so they cannot restore stale cards.

Apply the same privacy scrubber to metadata previews, text prefixes, error excerpts and tool-index listings as to transcript bodies; an apparently harmless prefix can contain infrastructure addresses, family chat IDs or credentials. Cache the whole-message masked projection by validated canonical hash when validating many small receipts from one long message; repeatedly scrubbing the entire body per receipt can time out finalization. Keep mask length accounting separate from visible original text, and compact only mask runs after slicing, never substantive evidence. Test URL masking against JSON-escaped strings and single-quoted URL lists before display: stop masks at both quote types and backslashes so masking an invite does not also conceal subsequent command/code evidence. If an overbroad privacy mask hid nonprivate evidence, re-display the affected spans with the corrected scrubber without new reading credit. Preserve existing candidate source metadata when rebuilding coverage: a legacy checkpoint renderer can regenerate `sources` and silently remove explicitly cited partial offsets; restore/merge the baseline source fields before final validation. Keep sensitive medical details out of editorial cards, and never claim earlier tool output was erased merely because later rendering was masked.

Before rendering tool receipts or metadata that embed source posts, inspect the whole normalized message for private health narratives in both Russian and English, not just medication/regimen keywords. Carry an established private-topic suppression decision across dependent replies and imported summaries: a generic follow-up can expose the same sensitive context without repeating the trigger word. Record conservative charged normalized spans, actually suppressed spans, accidentally displayed private prefixes, summaries, and genuine original-evidence reading separately; do not retrospectively label an exposed prefix as successfully suppressed. Keep all exposed private prefixes excluded from editorial sources and disclose the limitation without repeating their content. A public-post title does not make its embedded medical account public evidence. Prefer a nonmedical status/readback receipt for an operational pipeline claim; suppress private medical messages before slicing, exclude them from editorial source pointers, and disclose any earlier unmasked output without claiming it was erased.

Keep the progress ledger honest: inventory-only and text-profiled remain pending semantic review. If execution ends early, persist the exact unfinished work and state explicitly that the requested complete discovery is not delivered. Never fill the final topic list with search-selected anecdotes and call it a full pass.

Screen the whole canonical source for private health content before slicing even when the topic appears to be a plugin or button UX: quoted replies can embed regimens, and personal stage confirmations can omit formal medication names or contain spelling variants. Treat a keyword screen as a fail-closed backstop, not proof of privacy safety. Do not count an all-masked body as semantic reading; preserve its pending cursor or record a separate explicit privacy exclusion/projection. Keep a nonmedical UX correction separately without republishing the private example. Distinguish a technical “diagnosis” from a personal medical narrative to avoid suppressing unrelated evidence; if a false positive already hid a body, re-display it before reading credit.
